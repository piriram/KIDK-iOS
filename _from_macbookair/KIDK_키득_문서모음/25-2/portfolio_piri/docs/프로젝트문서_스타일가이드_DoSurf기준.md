# 프로젝트 문서 스타일 가이드 (DoSurf 기준)

이 문서는 `projects/dosurf.md`를 기준으로, 프로젝트 소개 md가 파일 전체에서 일관된 톤/서식/표기를 유지하도록 만드는 체크리스트다.

관련 문서:
- `docs/핵심구현_스타일가이드_DoSurf기준.md`: 핵심 구현 파트만 따로 보는 체크리스트

---

## 1) 파일 전체 구조(권장 순서)
```md
# {{PAGE_INTRO}} / 10 — 앱명 (영문명)

## 헤더
- 앱:
- 한줄 설명:
- QR:

## 스크린샷 라벨
- ...

## 기획 의도
- Problem:
- Solution:

## 프로젝트 정보
- 개발 기간:
- 플랫폼:
- 역할:
- 상태:
- 태그:

## 핵심 기능
1. 기능명: 한 줄 설명
2. ...

## 기술 스택
- 분류: 항목, 항목

---

## 핵심 구현
## 01 ...
부제 1줄

**문제**
...

**접근**
...

**결과**
...
```

허용되는 변형(기존 문서 호환):
- `핵심 구현`이 별도 페이지라면 `# {{PAGE_IMPL}} / 10 — ... 핵심 구현` 아래에 동일한 항목 템플릿을 유지한다.

## 2) 톤/문장(종결어미) 규칙
- [ ] 본문은 `했다/되었다/있었다` 중심의 `서술형 과거`로 통일한다.
- [ ] `합니다/됩니다/입니다`(합니다체), `해요체`, `음슴체`를 섞지 않는다.
- [ ] 같은 섹션/문단 안에서 `한다체`와 `했다체`가 섞이지 않게 한다.
- [ ] 과장 표현(예: "엄청", "대박") 대신 사실/수치로 쓴다.

빠른 탐지:
```sh
rg -n "(합니다|됩니다|했습니다|입니다|해요|하세요|해주세요)" projects/{dosurf,frameet,kidk,pilling}.md
```

---

## 3) 섹션별 서식 규칙

### 헤더
- [ ] 항목은 항상 `- 키: 값` 형태로 쓴다.
- [ ] 키 표기는 문서 간 동일하게 유지한다: `앱`, `한줄 설명`, `QR`.

### 스크린샷 라벨
- [ ] `-` 불릿 리스트로만 작성한다.
- [ ] 라벨은 명사형으로 짧게 쓴다(예: "지역 선택 화면").

### 기획 의도
- [ ] `- Problem:` / `- Solution:` 두 줄로 요약한다.
- [ ] 한 줄에 핵심만 넣고, 불필요한 수식어를 줄인다.
- [ ] 강조가 필요하면 핵심 키워드만 `백틱`으로 감싼다.

### 프로젝트 정보
- [ ] 날짜는 가능한 한 `YYYY.MM - YYYY.MM (N개월)`로 통일한다.
- [ ] 플랫폼은 `iOS 16.0+`처럼 `버전+` 표기를 쓴다.
- [ ] 역할은 책임 범위를 한 줄로 끝낸다(필요하면 핵심 역할만 `백틱`).

### 핵심 기능
- [ ] `1.`부터 시작하는 번호 리스트를 쓴다.
- [ ] 항목 형식은 `기능명: 한 줄 설명`으로 통일한다.

### 기술 스택
- [ ] `- 분류: 항목, 항목` 형태로 쓴다.
- [ ] 항목 구분은 `,`(쉼표+공백)으로 통일한다.

---

## 4) 핵심 구현 섹션 규칙(요약)
핵심 구현은 `docs/핵심구현_스타일가이드_DoSurf기준.md`를 우선으로 따른다.

파일 전체 관점에서 최소 체크:
- [ ] 각 항목은 `제목` + `부제 1줄` + `**문제/접근/결과**` 구조다.
- [ ] `문제:`/`접근:`/`결과:` 콜론 레이블로 쓰지 않는다.
- [ ] `* **문제**:` 같은 혼합(불릿+콜론) 서식을 쓰지 않는다.

빠른 탐지:
```sh
rg -n "(^문제:|^접근:|^결과:|\\* \\*\\*문제\\*\\*:|\\* \\*\\*접근\\*\\*:|\\* \\*\\*결과\\*\\*:)" projects/{dosurf,frameet,kidk,pilling}.md
```

---

## 5) 강조(백틱) 규칙
- [ ] 기술/프레임워크/패턴/클래스·프로토콜명은 `백틱`으로 감싼다.
- [ ] 핵심 규칙/정책/간격(예: `삭제 우선`, `1분 간격`)은 `백틱`으로 감싼다.
- [ ] 핵심 수치/전후 비교(예: `70%`, `1.2초`, `0건`)는 `백틱`으로 감싼다.
- [ ] 한 문장에서 백틱이 과도하면 1~3개로 줄여 핵심만 남긴다.
- [ ] 문장 전체를 백틱으로 감싸지 않는다.

---

## 6) 숫자/단위 표기 규칙
- [ ] 퍼센트는 `70퍼센트` 대신 `70%`로 쓴다.
- [ ] 시간은 `0.3초`, `약 2주`처럼 단위를 붙인다.
- [ ] 전후 비교는 `1.2초`에서 `0.3초`처럼 둘 다 단위를 유지한다.

---

## 7) 최종 리뷰 절차(권장)
- 1) `구조`: 섹션 순서/헤더 키/리스트 형식이 같은지 확인한다.
- 2) `톤`: 합니다체/해요체 혼입과 종결어미 혼합을 제거한다.
- 3) `강조`: 백틱을 핵심 스캔 포인트에만 남긴다.
- 4) `수치`: 결과에 최소 1개의 수치 또는 전후 비교를 넣는다.
