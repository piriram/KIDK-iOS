# 핵심구현 스타일 가이드 (DoSurf 기준)

이 문서는 `projects/dosurf.md`의 `핵심 구현` 섹션을 기준으로, 다른 프로젝트 문서(`projects/frameet.md`, `projects/kidk.md`, `projects/pilling.md`)의 핵심 구현 파트를 같은 톤과 서식으로 맞추기 위한 체크리스트다.

파일 전체(인트로 포함) 스타일 가이드는 `docs/프로젝트문서_스타일가이드_DoSurf기준.md`를 따른다.

## 적용 범위
- `projects/*.md`의 `핵심 구현` 파트
- 목표: 읽는 사람이 파일을 바꿔가며 읽어도 `구조`, `표기`, `종결어미(톤)`이 동일하게 느껴지게 만들기

---

## 기본 템플릿 (DoSurf 형식)
```md
## 핵심 구현

## 01 제목
부제 (한 줄로 핵심 설명)

**문제**
문제 서술. 상황과 제약을 포함한다.

**접근**
채택한 구조/기술과 선택 근거를 쓴다.

**결과**
측정 가능한 변화와 사용자 영향(그리고 한계가 있으면 한 줄)을 쓴다.
```

---

## 구조 체크리스트
- [ ] `## 핵심 구현` 헤더가 있다.
- [ ] 항목 헤더는 `## 01`, `## 02`처럼 `2자리` 번호를 쓴다.
- [ ] 항목마다 `제목` 바로 아래에 `부제 1줄`이 있다.
- [ ] 섹션은 `**문제**`, `**접근**`, `**결과**` 3개로 고정한다.
- [ ] `문제/접근/결과`는 `불릿(-)`으로 시작하지 않고, 헤더 라인 단독으로 둔다.
- [ ] 각 항목 사이에 빈 줄을 넣어 블록이 분리되어 보인다.

---

## 톤(종결어미) 체크리스트
- [ ] 본문은 `했다/되었다/있었다` 중심의 `서술형 과거`로 통일한다.
- [ ] `합니다/됩니다/입니다` 같은 `합니다체`가 섞이지 않는다.
- [ ] `해요체`, `음슴체`, 구어체 감탄(예: "너무", "진짜")을 쓰지 않는다.
- [ ] 동일 문단 안에서 `한다체`와 `했다체`가 섞이지 않는다.

빠른 탐지(터미널):
```sh
rg -n "(합니다|됩니다|했습니다|입니다|해요|하세요|해주세요)" projects/{dosurf,frameet,kidk,pilling}.md
```

---

## 강조(백틱) 규칙
DoSurf 기준에서는 굵게 강조를 남발하지 않고, 핵심 스캔 포인트만 `백틱`으로 처리한다.

- [ ] 기술명/프레임워크/패턴/클래스·프로토콜명은 `백틱`으로 감싼다.
- [ ] 핵심 규칙(예: 병합 규칙, 우선순위 규칙, 업데이트 간격)은 `백틱`으로 감싼다.
- [ ] 핵심 수치(예: `70%`, `0.3초`, `약 2주`, `1분 간격`)는 `백틱`으로 감싼다.
- [ ] 문장 전체를 `백틱`으로 감싸지 않는다.
- [ ] 한 문장에 백틱이 과도하게 많으면 1~3개로 줄여 핵심만 남긴다.

빠른 탐지(터미널):
```sh
rg -n "```|`[^`]*`" projects/{dosurf,frameet,kidk,pilling}.md
```

---

## 문장 구성 체크리스트
- [ ] `문제`: 사용자 상황, 왜 어려운지(제약/리스크), 기존 방식의 한계를 포함한다.
- [ ] `접근`: 무엇을 했는지와 함께 `왜 이 방식인지`(선택 근거)가 포함된다.
- [ ] `접근`: 핵심 구현 포인트를 2~4개로 제한해 스캔 가능하게 쓴다.
- [ ] `결과`: `전후 비교` 또는 `수치`가 최소 1개 포함된다.
- [ ] `결과`: 사용자 관점의 변화가 1문장 이상 포함된다.
- [ ] 필요하면 `한계/다음 개선점`을 1문장으로 끝에 붙인다.

---

## 서식/표기 통일 체크리스트
- [ ] `문제:` 같은 콜론 레이블을 쓰지 않고 `**문제**` 형식을 쓴다.
- [ ] `* **문제**:` 같은 혼합(불릿 + 레이블 + 콜론)을 쓰지 않는다.
- [ ] 영어 용어는 불필요한 한글 병기 없이 `의미가 필요한 경우에만` 한 번 설명한다.
- [ ] 날짜/기간은 가능한 한 구체적으로 쓰되, 본문 흐름을 깨면 부제 또는 결과로 옮긴다.

빠른 탐지(터미널):
```sh
rg -n "(^문제:|^접근:|^결과:|\\* \\*\\*문제\\*\\*:|\\- \\*\\*문제\\*\\*)" projects/{dosurf,frameet,kidk,pilling}.md
```

---

## 리뷰 절차 (권장)
- 1) `projects/dosurf.md`와 비교해서 `구조/레이블/톤`만 먼저 맞춘다.
- 2) 다음으로 `백틱 강조`를 최소 개수로 추가해 스캔 포인트를 만든다.
- 3) 마지막으로 `결과`에 수치/전후 비교가 빠졌는지 확인한다.
