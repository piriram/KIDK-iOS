# 포트폴리오 작성 지침

## 페이지 레이아웃 요구사항

### A4 가로 사이즈 (Landscape)
- **크기**: 297mm × 210mm
- **픽셀**: 1123px × 794px (96 DPI 기준)
- **비율**: 16:11.3 (약 1.42:1)

### CSS 설정
```css
@media print {
  @page {
    size: A4 landscape;
    margin: 0;
  }
}

.page {
  width: 297mm;
  height: 210mm;
  /* 또는 */
  width: 1123px;
  height: 794px;
}
```

## 포트폴리오 작성 원칙

### 1. 페이지 구성
- 각 페이지는 독립적으로 A4 가로 사이즈 준수
- 페이지 넘김 시 콘텐츠가 잘리지 않도록 구성

### 2. 콘텐츠 배치
- 헤더/푸터: 페이지 번호 및 간단한 네비게이션

### 3. 콘텐츠 보존 원칙 ⚠️ 중요
**절대 내용을 축소하거나 요약하지 마세요!**

- `portfolio_pages_full.md`의 내용은 **원본 그대로 유지**
- 특히 **"핵심 구현"** 섹션은 한 글자도 빠뜨리지 않고 전부 포함
- A4 한 페이지에 안 들어가면 **여러 페이지로 분할**
- 텍스트 크기를 줄이거나 내용을 요약하는 것보다 **페이지 수를 늘리는 것을 우선**

### 4. 긴 텍스트 배치 전략
긴 "핵심 구현" 섹션을 배치할 때:

#### 옵션 1: 여러 페이지 분할 (추천)
```
Page 3: 키득 - 프로젝트 소개
Page 4: 키득 - 핵심 구현 01, 02
Page 5: 키득 - 핵심 구현 03, 04
```

#### 옵션 2: 2단 레이아웃
```css
.implementation-content {
  column-count: 2;
  column-gap: 30px;
  text-align: justify;
}
```

#### 옵션 3: 작은 폰트 + 좁은 여백
```css
.detailed-text {
  font-size: 9pt;
  line-height: 1.4;
  padding: 10mm;
}
```

**우선순위**: 옵션 1 (페이지 분할) > 옵션 2 (2단) > 옵션 3 (작은 폰트)


## HTML/CSS 템플릿 가이드

### 페이지 컨테이너
```html
<div class="page" data-page="1">
  <header><!-- 페이지 헤더 --></header>
  <main><!-- 메인 콘텐츠 --></main>
  <footer><!-- 페이지 번호 등 --></footer>
</div>
```

### 반응형 고려사항
- 인쇄용: A4 가로 고정
- 화면용: 뷰포트에 맞춰 스케일 조정
- PDF 변환 시 페이지 경계 유지

### 변환 체크리스트

HTML로 작업할 때 매번 확인:

- [ ] `portfolio_pages_full.md`의 원본 텍스트를 **전부** 복사했는가?
- [ ] "핵심 구현" 섹션이 요약되거나 축약되지 않았는가?
- [ ] 한 페이지에 안 들어가면 **페이지를 추가**했는가?
- [ ] 문단 구조와 강조 표현이 유지되었는가?
- [ ] 기술적 세부사항 (코드, 숫자, 지표)이 누락되지 않았는가?

## 작성 시 주의사항

1. **완전성 우선**: 내용 보존 > 페이지 수 절약
2. **가독성**: 폰트 크기는 최소 9pt 이상 유지 (핵심 구현은 10pt 권장)

## 핵심구현 작성 체크리스트

### 템플릿

```markdown
## 0N 제목
부제

- 문제: ...
- 접근: ...
- 결과: ...
```

### 분량
                                            
      261 -| 항목 | 문장 수 |                         
      262 -|------|---------|                         
      263 -| 문제 | 3~5문장 |                         
      264 -| 접근 | 4~6문장 |                         
      265 -| 결과 | 3~5문장 |                         
      266 -| **항목당 합계** | **12~14문장** |        
      267 -| **프로젝트당 항목 수** | **3~4개**       
          - | 
          
### 체크리스트

- [ ] 제목과 부제가 있는가?
- [ ] 문제/접근/결과 구조를 유지했는가?
- [ ] 기술 용어와 구체적인 API/패턴을 명시했는가?
- [ ] 구어체, 음슴체를 사용하지 않았는가?
- [ ] 왜 이 방식을 선택했는지 근거를 포함했는가?

## 코드 기반 포트폴리오 보완 가이드

### 프롬프트 템플릿

```
코드 분석 후 보완해줘.

다음을 추출해서 반영해줘:
1. 실제 클래스/구조체/enum 이름
2. 사용한 프레임워크 API (메서드명까지)
3. 아키텍처 패턴과 설계 의도
4. 핵심 로직의 구체적인 흐름
```

### 코드 분석 시 찾아야 할 것

- [ ] **클래스/구조체명**
- [ ] **프레임워크 API**
- [ ] **디자인 패턴**
- [ ] **프로토콜/인터페이스**
- [ ] **핵심 enum/상태값**
- [ ] **외부 라이브러리**
- [ ] **구체적 수치** (Hz, 초, %, 바이트 등)

### 분량 및 구체성 기준

**핵심구현 1개당:**
- 기술적 도전: 2~3문단 (왜 어려웠는지)
- 해결 접근: 3~4문단 (구체적 API, 수치, 알고리즘)
- 배운 점/한계: 2~3문단 (측정 결과, 한계, 개선 방향)

**구체성 수준:**
- 프레임워크명: `HealthKit`, `CoreMotion`, `CMAltimeter`
- 수치: `10Hz`, `2G`, `0.5초`, `30초 버퍼`
- 측정 결과: `배터리 소모 15%`, `정확도 80%`
- 트레이드오프: `5Hz로 낮추면 배터리 절반, 정확도 하락`

### 보완 전후 비교 예시

**❌ 보완 전 (추상적)**
```
센서 데이터로 서핑 동작을 감지했다.
```

**✅ 보완 후 (구체적)**
```
CoreMotion의 가속도계에서 2G 이상의 가속도가 0.5초 이상 지속되면
"패들링 중"으로 판단했다. CMAltimeter로 1미터 이상의 상승 후 하강이
감지되면 "파도 탐" 이벤트로 카운트했다.
10Hz로 들어오는 데이터를 모두 저장하면 메모리가 소진되므로,
최근 30초만 순환 버퍼에 저장하고 화면이 꺼지면 1Hz로 낮춰
배터리 소모를 줄였다.
```
